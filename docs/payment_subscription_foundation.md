# Mercado Pago subscriptions foundation

This phase adds the backend foundation for recurring monthly tuition without changing the current student checkout.

## Current scope

- Persists subscription contracts in `public.student_subscriptions`.
- Keeps `student_billing_settings.monthly_fee` and `due_day` as the commercial source of truth.
- Allows at most one current subscription record per student.
- Stores provider identifiers and lifecycle metadata only.
- Never stores card number, expiration data, security code, or card token.
- Prepares the authenticated Edge Function `create-mercado-pago-subscription`.
- Starts the first recurring charge in the next monthly cycle.
- Keeps real subscription creation disabled until `MERCADO_PAGO_SUBSCRIPTIONS_ENABLED=true`.

## Edge Function actions

### preview

Returns the current server-side subscription quote:

- monthly amount;
- due day;
- first charge date;
- monthly frequency;
- current subscription, when one exists;
- whether subscription creation is enabled.

The request does not control amount, due day, or payer e-mail.

### create

Requires an authenticated student session and a tokenized card generated by the Mercado Pago client integration.

The function:

1. validates the active student profile;
2. reads amount and due day from `student_billing_settings`;
3. calculates the first charge in the next month;
4. creates or reuses an idempotent local draft;
5. calls `POST https://api.mercadopago.com/preapproval`;
6. persists only provider subscription metadata.

Creation remains blocked while the feature flag is disabled.

## Security

`student_subscriptions` has RLS enabled and no direct browser grants. Only `service_role` can read or mutate it directly.

The Edge Function requires a valid student JWT and revalidates the user with Supabase Auth. It prefers the new Supabase publishable/secret key bundles and keeps compatibility with the existing legacy variables.

The Mercado Pago Access Token remains an Edge Function secret and is never sent to the browser.
